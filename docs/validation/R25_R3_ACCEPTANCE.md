## R3：经验形成与实际采用

[中断记录](r3-live.json) 只有首个任务与三个已记录请求，没有最终完成标记；tokens=0 是未结算，不是零成本。

[第一份完整报告](r3-live-complete.json) 的产物检查通过，但审阅发现：候选条件绑定 `name,amount`，第二任务明确说它不适用于 `city,units`；脚本却因为同样使用 utf-8-sig 而判断“已采用”。保留原工具轨迹和 original_harness_passed，审阅后将 passed 改为 false，并记录原因。该轮 10 次请求、19,188 tokens 不计作进化验收通过。

修复包括：

1. 提炼提示区分机制与任务参数；适用条件保留编码/格式，列名、文件名和样本值不得写成普遍条件或预期。
2. 受限验收工具只在模型明确采用指定候选时接受其 experience_id。宿主同时检查该 ID、实际操作、输出内容和输入字节未变；不能仅凭参数相同或模型口头称成功。
3. 不适用任务要求没有采用 ID，并以逐字节复制结果核验。普通产品学习 API 的 adopted 仍由用户/宿主负责真实性；这不是自动裁判。

[最终报告](r3-live-reviewed.json) 完整通过：

- 第一份带 BOM 的 CSV 提取 name 列，生成带来源的候选；适用条件以 `{col}` 表达列参数。
- 独立文件改为 city 列，模型判断候选适用，在成功提取操作中明确填写候选 ID；宿主确认输出与输入不变。
- 无 BOM 的原样复制任务明确不采用候选，输出逐字节相同。
- 记录试用反馈后，宿主认可使经验进入普通检索；撤回后检索为空。

最终轮为 **10 次聊天请求、18,246 报告 tokens**，未新增 embedding 调用。两个任务仍同属 CSV 处理，且没有无记忆控制组，不能据此宣称成功率、效率或泛化收益提升。

原计划让真实模型调用本机 bash，自动审批因工作目录不构成访问隔离而拒绝。实际执行的替代方案完全禁用 bash/任意代码，仅开放无路径参数、操作与编码白名单约束的固定临时 CSV 工具；没有绕过该限制。
