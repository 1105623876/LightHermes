# R4.1 读取策略比较结果（2026-10-02）

**结论：三组正式评测均9/9通过；本轮没有发现线索方案的质量收益，且它更费 tokens/请求。按需查阅使用的报告 tokens 少约8%，但模型请求更多，列为后续复验候选，产品默认值保持不变。**

## 实际完成的比较

执行前协议：[R41_PROTOCOL](R41_PROTOCOL.md)。grok-4.6 / BAAI/bge-m3；阈值固定0.46。两项开发检查与九项独立评测跨三组，共33次任务运行。每项只有一次运行，轮换组顺序，没有择优重试、阈值拟合或模型裁判。索引由同一组 active 正文预建，再复制到各任务独立实例。

- 自动短片段：现行 seed/search/read 展示。
- 经验先给线索：事实预览保持原样；经验先展示 applicable_when 和 ID，read_memory 才读取方法。没有额外摘要请求。线索变短会改变同一预算内可展示内容，不能假定所有组的展示条数完全相同。
- 按需查阅：不做自动 seed 查询，仍提供同样的 search/read 工具，由当前主模型决定查询。没有第二个规划器。

三组的知识内容、模型、问题、任务工具、调用上限相同。经验为宿主合成 active 夹具，用于控制读取方式，**本轮不检验经验学习或自动认可是否有效**。没有任意 shell/模型代码执行、真实记忆修改、持久化格式变更或新依赖。

- 线索组相对短片段组：聊天 tokens 多10,786（约24.6%），模型请求多5次，最终注入总量也未减少。小线索带来的节省被后续搜索、读取和对话轮次抵消。

## 正确性与污染分别看

九项覆盖两项跨语言事实、两个同主题无答案问题、纠正后的新事实、遗忘后的无答案问题、适用经验执行、不适用的逐字节复制和无关计算。

- 三组均9/9答案或产物正确，事实来源判据通过；无答案问题均返回null，没有无依据肯定回答。JSON格式全部有效。
- 三组都没有“应查却未看到/读取目标记忆”的情况。适用经验均有正确方法参数、经验ID和产物相符；复制反例没有错误经验声明或字节改动。
- 全33次运行的记忆总注入都不超过4000字节，seed不超过1500字节。
- 短片段 / 线索 / 按需组分别展示37 / 39 / 29次“非直接目标条目”（按每任务去重汇总，根据夹具目标ID事后汇总）。这是潜在无关暴露的描述，不是实际错误率：同主题记录可能作为背景，但没有回答该问题的目标属性。
- 例如无关算术任务，两个自动组各展示4条记忆，按需组没有查询或展示。三组仍都答对。**召回了非目标内容，并不必然使模型答错。** R4的检索层失败诊断仍有效，但不能直接外推为端到端误答。

需要保留的限制：题目明确允许未知回答null，并使用结构化输出；开放式长回答可能更容易受干扰，不能据此宣称污染已解决。事实题较简单、经验方法已提供，每题每组只有一次运行，不能将约8%的tokens差异当作稳定收益。

纠正和遗忘在本轮索引预建前已经完成，因此这里验证新实例能读取正确的当前状态，不证明长会话旧上下文即时失效，也不是对动态向量失效的重新验收。原相应存储回归继续保留。

## 决策

1. **不把线索展示加入产品。** 在本轮没有额外正确性收益，却多花调用和tokens；保留验收脚本中的对照即可，不增加配置项或维护第二套正式读取逻辑。
2. **按需查阅进入复验候选，暂不替换默认。** 它通过本轮无新增错误的门槛，并减少报告tokens和非目标暴露，但增加请求数；下一次如复验，应先固定真实使用任务与重复预算，再判断取舍，不挑本轮有利题目重跑。
3. **当前短片段策略继续作为默认。** 不再因检索层有非目标候选就直接大改架构。向量 JSON 解码与空间成本已有明确规模瓶颈，可作为下一独立收敛切片；本轮没有实现紧凑向量或树索引。
4. 自进化的失败案例学习与收益证明仍是另一个问题，本轮的读取比较不替代它，也不改变人工认可边界。
