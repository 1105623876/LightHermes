# R4 验收与决策（2026-10-02）

**结论：规模保护与受控闭环可运行；召回污染和跨任务收益门槛尚未全部通过。保持语义检索显式启用、经验人工认可；不接入树索引、不开放自动激活。**

协议在本轮新结果前冻结于 [R4_PROTOCOL](R4_PROTOCOL.md)。全部数据为临时合成数据；配置模型为 grok-4.6 / BAAI/bge-m3，不涉及真实记忆迁移。原 LoCoMo/holdout 未运行。脚本没有新增依赖，模型只能调用固定临时数据工具，没有任意 shell/代码执行。

## 规模与增长

Mac arm64、Python 3.12.14；1024 维固定本地替身，正常 MemoryStore/SemanticIndex API；当前 JSON 向量格式不变。新连接首查不是 OS 冷缓存，热查仅 10 次，p95 是探索性样本值，不宣称稳定尾延迟。索引构建包含本地替身生成，不代表远程 embedding 耗时。

| 条目数 | 写入 / 向量构建 | 新连接首查 | 热查询 p50 / p95 | FTS p50 | 管理磁盘 / 向量有效载荷 |
|---:|---:|---:|---:|---:|---:|
| 100 | 0.08 / 0.05 s | 16.3 ms | 16.2 / 16.3 ms | 0.037 ms | 2.52 / 2.14 MiB |
| 1,000 | 0.90 / 0.57 s | 161.5 ms | 160.6 / 175.0 ms | 0.110 ms | 24.45 / 21.62 MiB |
| 10,000 | 18.17 / 12.39 s | 1663.1 ms | 1611.7 / 1647.6 ms | 0.135 ms | 243.64 / 216.42 MiB |

- 万条单独剖析：SQLite 读取约 52 ms，JSON 解码约 1360 ms，Python 内积约 213 ms。当前 O(n·d) 扫描的首要实测开销是向量表示/解码，不能只归因于距离比较。
- 万条使用约 243.64 MiB，占默认 256 MiB 上限约 95%；这是合成短事实，真实长正文/事件会更早触及容量。尚不能把 256 MiB 作为支持万条长期日常工作负载的发布保证。
- 每批向量最多 16 条；初建分别只嵌入 100/1000/10000 条正文。查询与纠正没有重嵌入旧正文；语义候选实测最多 50，最终返回最多 4。
- 去重沿用同 ID，纠正/遗忘失效 FTS 和向量；其他 scope 无结果。所有规模检查通过，4000 字节总预算内停止注入。测试最初未捕获预期预算异常，修正为显式记录后运行；未修改产品预算行为。
- 同一会话 200 回合，seed 每次 226 字节，仍只有一个 active 事实，没有随事件历史增长而扩大注入。增长的原始事件依旧占磁盘，不等于零存储增长。
- 首次规模结果后仅补充候选数/批次与长会话仪表重新测量，没有改实现、阈值或挑选最快结果。当前 JSON 保存补充后的完整一次测量。

原始结果：[r4-scale.json](r4-scale.json)。复现：`.venv/bin/python scripts/r4_scale.py --output <路径>`。

## 树索引：验证了剪枝条件，没有添加产品框架

标准库精确 VP-tree 与使用同一 `math.dist` 内核的平扫比较，均在内存中；10,000 个归一化向量，top-5，10 个查询。8/1024 维与分散/聚簇分布均固定；四组 top-5 全部一致。这个实验隔离索引剪枝，不能拿其内存耗时直接与包含 SQL/JSON 的生产路径比较。

| 维度 / 分布 | 平扫 p50 | VP-tree p50 | 平均访问向量比例 | 建树 |
|---|---:|---:|---:|---:|
| 8 / independent | 0.92 ms | 0.84 ms | 42.7% | 20.2 ms |
| 8 / clustered | 0.97 ms | 0.18 ms | 8.8% | 30.2 ms |
| 1024 / independent | 40.80 ms | 44.82 ms | 100.0% | 426.6 ms |
| 1024 / clustered | 43.87 ms | 8.13 ms | 15.3% | 567.3 ms |

1024 维分散数据访问 100% 向量，树反而略慢；人为形成的聚簇数据访问约 15%，有约 5.4 倍查询加速。用户提出的方向值得保留，但不能保证 O(log n)，也不能由合成聚簇结果推断真实 BGE 记忆同样受益。本轮未测试 ANN、真实向量分布、动态树更新或 scope 过滤维护成本，不据此作库选型。

决策：先测紧凑向量表示能否同时改善空间与读取，再用实际向量分布判断索引；不引入常驻服务、第二份事实存储或预先设计可插拔后端。持久化格式变更另行审查重建影响。

## 固定阈值语义质量

真实 BAAI/bge-m3，沿用先前开发阈值 0.46，本轮不调参。四条新中文事实，对应四个英文查询；另有两个主题相近但事实无答案的问题。

- 词法路径：跨语言正例 top-1 为 0/4，无答案问题保持空结果 2/2。
- 混合路径：跨语言正例 top-1 为 4/4；但每次还返回 1–2 条非目标记忆，两个无答案问题均误召回，拒绝率 0/2。
- 将“两位维护者审核”纠正为“三位”后，新条目可召回、旧条目退出；遗忘后旧/新均不再出现。但同主题其他事实仍会被召回，**索引失效正确不能证明检索答案相关**。
- 10 次 embedding 请求，供应商报告 165 tokens；全部处于 hybrid，无传输错误。报告 token 数仅记录供应商口径，不作为通用中文预算换算。

原始结果：[r4-semantic.json](r4-semantic.json)。四个正例与两个难负例太小，不能给出普遍质量估计；已暴露的问题足以否定“0.46 已解决污染”。下一步在独立开发集研究自动 seed 的更严格筛选，保留主动搜索渠道；不用本组样本调阈值再重新宣称通过。

## 三配置完整任务回放

开发阶段各用一个 BOM CSV、金额字符串任务学习候选，再各用一个独立开发任务试用；两条经验均具备宿主核对的实际采用、正确产物和输入未变证据。四项开发任务通过，15 次聊天、40,593 tokens、约 113 秒，均计入总成本。

冻结回放为两个新列名的 BOM CSV、两个新金额数组、字节复制与整数原样返回反例。每项在 none / facts / experience 各跑一次，轮换顺序；所有配置有相同工具、模型、每任务 4 次模型/工具上限，任务说明始终可查阅。各任务从同一开发库快照创建新实例，对照只改变可用 active 条目；不继承开发对话上下文。

| 配置 | 通过 | 模型 / 工具调用 | 固定处理工具错误 | 报告 tokens | 任务耗时合计 |
|---|---:|---:|---:|---:|---:|
| none | 6/6 | 22 / 21 | 0 | 40,171 | 89.1 s |
| facts | 5/6 | 21 / 21 | 3 | 40,632 | 153.8 s |
| experience | 6/6 | 18 / 18 | 0 | 46,829 | 104.3 s |

- CSV：三配置均 2/2；事实组与经验组均无失败尝试，因此没有观察到经验对事实基线的额外收益。
- 金额：三配置均 2/2；事实组两个任务都先出现一次错误，经验组均避免该错误。无长期记忆组也没有出错，所以不能把这组差异推广成经验必然优于基础模型。
- 经验组四项相关任务均通过经验 ID + 方法参数 + 产物检查确认实际采用，两个不适用任务均不采用，且产物正确。
- 事实组整数原样返回失败：模型把非经验 ID 填入 `experience_id`，工具拒绝后耗尽预算。此处是可观测工具契约错误，不能表述为“错误经验改变了整数算法”。该 ID 校验是所有配置相同的验收约束；失败与预算上限保留，未补跑。
- 经验组相对事实组少 3 次模型请求，但多 6,197 tokens，另有学习准备成本；因此本轮不支持“总成本更低”。耗时受网络/服务波动影响，不作为因果延迟收益。
- 六任务各一轮，无随机重复、置信区间或复杂现实任务，不能声称统计泛化。工具说明本身已给出可用方法，基础模型可独立完成；不刻意削弱基线来制造记忆收益。

**预注册门槛未通过**：两类任务都要有可归因额外收益；本轮只有金额相对事实基线减少试错，CSV 无额外改善。保持 `evolution.enabled: false` 默认值与显式 trial/approve，不新增自动激活。

网络受限的首次尝试全部为连接错误（22 次尝试、0 报告 tokens、没有工具执行），见 [原始记录](r4-replay-network-blocked.json)。获得联网执行后完整重跑固定矩阵，没有选择性重试个别失败。有效联网轮 76 次聊天、168,225 tokens、约 460 秒；包含前述准备与18次评测。连同网络受限尝试共 98 次聊天尝试，低于预先110次上限；embedding 另计10次。报告中的 `complete` 仅表示矩阵已遍历，不代表任务成功或收益通过。

原始结果：[r4-replay.json](r4-replay.json)。复现需明确真实调用授权：`.venv/bin/python scripts/r4_replay.py --live --output <路径>`；固定数据、方法、成功判据都在脚本中，不依赖模型裁判。
