# R4.1 读取策略比较：运行前协议（2026-10-02）

本轮只在验收脚本中替换 RuntimeMemory 的展示策略，不改产品默认值、schema 或学习权限。使用已配置聊天/embedding 模型与临时合成库；没有任意 shell、代码执行或真实用户记忆。原 R4 样本不用于本次拟合。

## 三组与控制变量

- `snippet`：当前 seed/search 短片段，read 按原实现展开。
- `clue`：同一排序、候选与预算；事实保留原短片段，经验的 seed/search 仅展示既有 applicable_when 和 ID，read 才展示方法。没有额外摘要调用或新持久字段。
- `demand`：seed 为空且不执行自动查询，search/read 与 snippet 一样，由主模型决定何时查阅。

三组使用同一模型、工具说明、问题、独立的新实例及同一数据库快照；轮换顺序。4000字节记忆总预算、seed1500字节、两次主动搜索不变；每任务最多4次聊天/4次工具，输出最多600 tokens、超时45秒、SDK retries=0。不进行经验学习或阈值调节。经验为明确标注的宿主合成夹具，不能据此宣称学到经验。

## 样本与判据

脚本运行前固定两项开发检查（事实、适用经验），以及九项独立评测：两个跨语言事实、两个同主题无答案问题、纠正后的事实、遗忘后的无答案问题、适用经验、不适用的原样复制、无关简单计算。各组三轮次中的每个样本只运行一次；开发检查只检查实验机制，不用来调阈值或挑选提示。

事实回答用统一 JSON `{answer: string|null, evidence_ids: [...]}` 格式；仅按精确预期和有效来源检查，记录格式失败与答案错误的区别。无答案应返回 null，不要求一定搜索，但单列是否未查就断言未知；空检索不作为已证明全库无答案。行动案例使用固定无路径工具，宿主检查实际输出字节与输入不变；experience_id 只用于观察采用，不以填错ID拒绝执行，避免重现R4工具元数据干扰。

分别记录：答案/产物正确、来源充分、无答案时的无依据肯定回答、应查未查（需要记忆但既无相关展示也无有效读取）、错误经验采用、候选展示ID、实际读取ID、记忆字节、工具和模型次数、tokens、embedding调用/报告tokens、耗时、异常。输出 JSON 仅用于可复查判据，不用第二个模型裁判。

索引仅用当前 active 正文预建一次，再复制到各组；正文 embedding 准备成本单列，动态查询按组计入。阈值固定0.46，远程失败显式记录；连续三项基础设施失败停止，保留未完成项，不选择性补跑。

## 成本与决策

最多140次聊天尝试、110次embedding尝试，包含开发检查和准备；达到预算立即停止。本轮只给方向性证据，不估计统计显著性或自动推广默认策略。

仅当候选策略没有新增任务错误、无依据断言或错误经验采用，并且降低总成本或污染暴露，才列为后续候选；未改善/样本不足时保持当前默认值。总成本要考虑额外查阅轮次，不能用 seed 更短就宣称省钱。开发失败先检查实验实现，修复必须另记，不能修改未见答案判据补分。
