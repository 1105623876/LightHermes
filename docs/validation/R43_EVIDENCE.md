后续进展（2026-10-22）：隔离启动问题已修复，真实模型诊断已开始；文本任务通过，事务任务接口超时，经验收益仍待验证。见 [R4.3真实失败诊断](R43_DISCOVERY.md)。下文保留2026-10-15的原始记录。

## 发现与改动

旧 `Experience.learn()` 只选取最近6个工具输出。当bash输出只有 `verified` 或退出状态时，学习模型看不到实际采用的方法。数据库保存了调用意图，但它没有进入提炼材料；候选来源也只关联观察。这会让“可验证经验”的方法依据不完整。

当前实现按同一scope/session/turn读取最近至多24条相关事件，配对调用意图与工具结果，再提供最后6组证据。仅使用已持久化且经过现有脱敏处理的内容，不直接取未处理的内存参数。每组操作与观察文本合计至多1000 UTF-8字节，其中操作至多600字节；来源标识、状态与JSON封装另计。

- 每组包含操作来源、命令/参数、观察来源和输出；候选关联两类事件。
- 缺少对应意图时标记 `action_missing`，被截断时标记 `truncated`。过旧、其他回合、其他scope或已排除的动作不能被拿来补齐；同一个调用ID重用时按当前批次匹配。
- 提炼提示明确禁止猜测缺失做法，工具正常退出不能代替宿主目标检查。
- 不增加模型调用、后台任务、存储表或配置。一次显式提炼调用、独立试用和人工认可边界保持不变。

取证仍有上限：特别长的命令或超出回看范围的调用可能只留下部分内容。标记说明证据不完整，并不保证模型一定拒绝无依据归纳；这需要真实模型验证。常见凭据脱敏也不是通用秘密检测。

## 实际验证

两类任务由测试替身给出已审查的固定命令，经产品bash与SQLite实际执行：

| 案例 | 实际失败 | 修复与独立核验 |
|---|---|---|
| 文本字节保留 | 文本读写把CRLF变成LF，违反只改目标字节的要求 | 按字节替换；核对BOM、换行、输入未变，再换另一份输入试用 |
| SQLite批量事务 | 自动提交下部分插入先落盘，后续唯一约束失败未撤销前面改动 | 使用SAVEPOINT保护该批次；独立库验证调用者未提交数据仍保留、仍能自行回滚 |

两类回放都完成失败 → 修复 → 宿主核验 → candidate → 独立试用 → 宿主认可。学习请求中包含实际方法，候选来源可追到相应命令和输出。**这些命令与候选是确定性测试数据，不是模型自主发现的失败，也不是学习收益证据。**

将修改前的 `Experience` 从Git载入独立测试进程，保持工作树不变，两项回归均失败：学习材料中分别找不到 `write_bytes` 和 `SAVEPOINT`。新实现通过同样的检查。

另外覆盖其他回合/scope与排除来源、操作与观察片段预算、已脱敏参数三项回归。全量离线 **298 passed（3.80秒）**，包含5项新增检查；此前R4.2为293项。复现入口仍为 `.venv/bin/python -m pytest tests`，没有新增实验框架。

## 真实收益试验尚未启动

本机现有 `sandbox-exec` 探针未能通过：普通执行报 `sandbox_apply: Operation not permitted`；两次受授权的隔离诊断中，Python和最小echo子进程均出现SIGABRT（退出码-6），没有得到可用的执行隔离。连续失败后停止该路径，没有安装容器或把cwd当成隔离继续运行模型命令。所有探针仅使用临时文件，测试后已清理。

本轮没有读取env密钥、调用付费模型、运行模型生成的任意命令、修改真实记忆或推送。以前R3的真实bash审批限制也没有因这次离线回放而解除。

后续诊断按以下顺序推进，不能把离线夹具计入真实模型通过数：

1. 先确定可用且已授权的执行环境，验证任务目录外读写和联网边界；保持所有对照组相同权限，不把模型命令直接放到未隔离的宿主执行。
2. 开发诊断只跑上述两类任务，每类最多6次模型请求、6次工具调用，共最多12次；单次输出上限1800 tokens、超时45秒、无自动重试，连续3次服务故障终止。记录实际模型与端点标识，绝不记录密钥。调用前确认当轮模型授权；这些数字是待执行预算，不是本轮已使用成本。
3. 只有模型实际造成错误产物或错误操作，才作为失败学习入口。初始项目已有缺陷、网络故障和人为缩短预算不能冒充模型能力失败；若两类均能直接完成，就报告未找到学习需求，不临时加难题制造收益。
4. 从实际失败与宿主反馈提炼候选，独立试用合格后，再冻结新任务进行无长期记忆/事实/事实加经验对照。至多两条提炼、两项独立试用、四项正例和两项邻近反例；全阶段总请求上限140（含开发），所有失败与学习成本都保留，执行前补齐固定任务清单。
