## 借鉴什么，以及明确不搬什么

### 1. Hermes：发现线索和读取详情分开

[`skills_list` / `skill_view`](https://github.com/NousResearch/hermes-agent/blob/02fc8f7de791105fe47162d59ceb2e8ce8847f9e/tools/skills_tool.py#L234) 先展示名称与描述，全文由后续调用读取。[历史检索](https://github.com/NousResearch/hermes-agent/blob/02fc8f7de791105fe47162d59ceb2e8ce8847f9e/tools/session_search_tool.py) 用 FTS5 和有界片段查原始消息，无额外模型摘要调用，并区分自动化与交互会话，避免大量重复记录占据结果。

**适用判断**：LightHermes 已有 preview/read、来源和字节上限，并非缺少渐进读取；缺的是自动 seed 仍会把“主题相关”的片段送入推理。可借鉴“线索不等于正文”的边界，不能把又一层摘要当成已解决相关性。Hermes 的会话冻结记忆有提示缓存收益，但不适合照搬到我们要求纠正/遗忘及时生效的路径。多 provider、后台同步和平台体系不搬入。

### 2. nanobot：只整理新材料，变更能够检查

[`build_dream_prompt`](https://github.com/HKUDS/nanobot/blob/d0d0a44e57632c3d269e511339cff7ddb698e62e/nanobot/agent/memory.py#L527) 按消费游标取有限批次，默认最多20项，每项有文本限制；[手动 Dream](https://github.com/HKUDS/nanobot/blob/d0d0a44e57632c3d269e511339cff7ddb698e62e/nanobot/command/builtin.py#L498) 区分正常结束和未完成，结合实际文件差异记录变更，并提供恢复入口。

**适用判断**：如果以后需要批量整理，用 SQLite 已有事件和来源标识实现增量消费；不全库重写，不为此另设 JSONL/Git 记忆库。当前逐任务 learn 已有 attempt 标记，不急着引入新游标。正常结束不能证明归纳正确，仍需我们的宿主验证边界。定时 Dream、修改 SOUL/USER 和后台守护不搬入。

### 3. RSIAgent：围绕实际弱点练习，评测时冻结记忆

[官方项目](https://github.com/AetherLabsAI/RSIAgent)采用探索、执行和独立验证角色；[架构说明](https://github.com/AetherLabsAI/RSIAgent/blob/main/docs/ARCHITECTURE.md)将练习/记忆更新与冻结记忆评测分开，基础设施错误不冒充学习成功或任务失败。

**适用判断**：学习材料应来自有明确弱点的开发任务；成功和失败都可以提供证据。之后换输入/条件验证，未见评测只读经验。LightHermes 已有执行器和宿主验证，不必增加三个 Agent。先手工选少量真实失败点，也能借鉴这种顺序。其报告含选择性重试/不同预算等说明，不能直接把论文分数当作严格配对收益，亦未在本地复现。

### 4. ReasoningBank：记可复用的教训，避免保存任务流水账

[论文](https://arxiv.org/abs/2509.25140)和[官方代码](https://github.com/google-research/reasoning-bank)从成功与失败轨迹中提炼可迁移策略；其软件工程实验建立在 mini-swe-agent 上。

**适用判断**：现有 experience 的“适用条件、方法、验证”结构足够。下一次试验重点应是“错误尝试—实际反馈—有效修正”的对比，而不是再设计一种记忆层。论文使用自评/模型裁判的部分不替代我们的检查结果；并行多次尝试的额外算力方案暂不采用。来源中的内部推理不作为应完整保存的要求，保存可观察的操作与结果即可。

### 5. RRSI：每次只改少量机制，收益必须覆盖代价

[RRSI 论文](https://arxiv.org/html/2609.24972v1)约束每轮修改数量，保留被否定的假设，检查评测泄漏、随机波动与成本增长；[官方代码](https://github.com/google-research/rrsi)是研究实现。

**适用判断**：把这些约束用于我们的开发/经验验收：一次验证一个改变，保留失败，未见任务复核，同时计算准备和运行成本。无需照搬自动修改任意源码的搜索系统，也不新增在线“质量分”。删除长期无收益机制是一条开发决策，不能据此自动删除用户事实或以命中次数判断真伪。

### 6. Skill-RSI：保留版本对照与失败实验

[项目说明](https://github.com/justinwetch/Skill-RSI)围绕技能提出变体、运行对照、选择版本，并保留失败方向。

**适用判断**：以后修订一条经验，保留旧版和相同预算下的对照，而非让模型觉得新版更好就覆盖。现有 supersedes、来源和审计可承载；暂不安装插件、UI 或自主研究循环。没有在本轮运行它，不能把 README 流程视为效果已验证。

### 7. 上下文工程与极简主循环

[Anthropic 的上下文工程说明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)提出保留轻量引用、运行时按需加载，并允许少量预加载与主动查阅组合。[mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent)继续作为简单执行循环参考。

**适用判断**：把复杂度放在更好的记忆内容和验证样本上，主循环复用已有 bash、search_memory、read_memory、update_memory。不新增独立检索 Agent、第二个规划循环或每回合付费重排器。

## 对 LightHermes 下一步的具体影响（提案，未实现）

### 优先做一个读取策略实验

当前 R4 把“无答案问题却召回了相关条目”判作检索失败，这是有价值的诊断；但还需要测量它是否导致最终编造答案或错误操作。不能仅优化空结果比例，把有用召回一起消掉。

固定新的开发集和未见集，比较三种策略：

1. 当前自动短片段 seed，作为基线。
2. 对候选只展示有界线索：经验优先展示现有 `applicable_when` 与 ID，方法通过 `read_memory` 读取；不新增一次摘要模型调用。事实不能含糊改写成无法判断的标题。
3. 不预填语义片段，通过当前模型和既有 search/read 按需查阅，作为低污染对照；不能默认它必然更好，因为可能漏掉该查的记忆、增加轮次。

候选线索也会污染，第二种策略不是安全证明；现有4000字节与调用预算不变。样本至少覆盖跨语言正例、同主题不同属性的无答案问题、纠正/过期决定、明确适用与近邻不适用经验。记录最终任务正确率、无依据断言、应查未查、实际采用、总 tokens/请求数及成本。以独立开发集确定规则，未见集只做验收，不反复调到全绿。这比先增一套 reranker 更符合现有规模。

### 自进化继续推进，但把精力放在学习材料与对照

R4 的固定工具说明已经给出正确方法，强模型在无记忆组6/6，留给经验的改善空间很小。它证明了受限闭环，却不是足以判断所有自进化价值的任务集。

下一次选来自实际开发使用、存在稳定重复错误的任务族；保留自然错误/反馈，不能故意阉割无记忆基线。开发期用现有 learn 保存一条具体候选，独立试用后冻结。比较无长期记忆、事实、事实加经验时，工具和总预算相同，全部失败与学习成本计入；必要的重复次数和预算在运行前确定。出现改善再扩大范围，暂不开放通用自动激活。当前 `learn` 已接收 verified_failure，无需再建立独立“失败记忆库”。

### 性能按测量顺序优化

外部资料没有推翻本地测量：当前万条向量的主要成本是 JSON 解码和体积。上述读取实验可能减少不必要的查询次数，但不会改变单次扫描复杂度。紧凑向量表示仍排在新增树/ANN之前；格式影响单独审查。资料检索不是对新索引性能的验证。
