> 更新：2026-09-22 · 状态：已确定的开发方向，尚未实现的项目均保持未勾选。
> 定位：单用户、本地优先、可嵌入的轻量 Agent。通过 bash 完成实际任务，通过跨会话记忆保持连续性，通过经过验证的经验改善后续行动。

## 0. 后续 AI 必须先读

1. 本文是后续开发的设计与顺序依据，取代旧 ROADMAP 中尚未实施的产品规划。当前用户指令与适用的 `AGENTS.md` 仍优先；代码、测试和实际数据决定“已经实现什么”。
2. `README.md`、`PROJECT_STATUS.md` 和旧设计文档中“四级记忆、自适应、自动进化已完成”的描述属于旧基线，不代表本文验收通过。实施时同步相关说明，不把计划写成现状。
3. 每次只推进一个可验收切片。先读相关实现、测试、Git 差异；保留用户修改。不得借“按 ROADMAP 开发”顺手迁移真实数据、删除历史产物、重跑付费实验、安装全局依赖或发布。
4. 第一个实现任务是 R0。R0 后按 R1 → R2 → R3 → R4 推进。不得先做插件、图谱、独立规划器，或整仓重写；发现阻塞可以先修直接相关问题并说明依赖。
5. 交付必须说明行为变化、验证结果、剩余限制，以及删除或替代了哪些旧复杂度。只有真实验证通过才勾选。减少行数不是通过标准，新增开关也不是解决复杂度。
6. 本轮只重写路线图，没有改变运行时默认行为，也没有授权真实记忆迁移。存储迁移与公开接口破坏性变更需先给出可审查方案并取得相应授权。

**核心判断：先让 Agent 能行动，让记忆可靠地进入下一次行动，再让成功经验可验证地改善行动。三者共享一个循环。**

## 1. 已定取舍与产品边界

| 决策 | 要实现的行为 | 不继续扩展的方向 |
|---|---|---|
| bash 是核心能力 | 开箱可发现、完成执行授权后可用；读文件、搜索、编辑、测试复用 shell | 为每种命令建立专用工具与插件 |
| 一个 Agent 循环 | 模型 → 工具 → 观察 → 模型，完成、失败、取消或预算耗尽后统一收尾 | 独立记忆 Agent、进化 Agent、Planner、事件总线 |
| 两类持久内容 | 会话记录保存发生的事情；记忆条目保存可复用事实与经验 | 工作→情景→语义的自动层级搬运 |
| 记忆与自进化同属主线 | 记忆减少重复说明，经验减少重复试错 | 将自进化无限延期，或用模型自评冒充验证 |
| 上下文按需构建 | 允许零召回，先给短卡片，再按来源读细节 | 全部偏好、技能、失败报告、历史摘要常驻提示词 |
| 轻量依靠少概念 | 复用现有适配器、工具分发、检索和压缩 | 用大量兼容开关维持所有旧路径 |
| 本地单用户 | 明确用户级与项目级作用范围 | 多租户、共享记忆、网络 Channel、插件市场 |

自进化在本项目中的定义：**从有结果证据的任务中产生可撤回的经验，在后续任务中验证其收益，必要时固化成短技能。** 不自动修改自身代码、权限、依赖或系统规则；不做 RL、在线微调或自建训练平台。

参考 mini-swe-agent 的短主循环、线性消息历史和独立命令执行。它的简洁值得借鉴，但其宣传中的核心行数不等于整个项目规模；LightHermes 不以“100 行”或“所有能力只能通过 bash”作为目标。记忆读写保留少量结构化工具，保证作用域、来源、更新和索引一致性。[官方介绍](https://github.com/SWE-agent/mini-swe-agent)、[主循环实现](https://github.com/SWE-agent/mini-swe-agent/blob/main/src/minisweagent/agents/default.py)、[本地执行实现](https://github.com/SWE-agent/mini-swe-agent/blob/main/src/minisweagent/environments/local.py)（参考日期：2026-09-22；后续若照搬实现需重新核对版本）。

## 2. 最小架构与职责

```text
CLI / Python API
        ↓
Agent：会话、消息、工具循环、统一预算与收尾
        ├── Model adapter：复用现有供应商适配
        ├── bash：通用行动与可观察结果
        └── Memory：检索、读取、写入/纠正/遗忘
                  ├── 会话记录：消息、工具观察、任务结果
                  ├── 记忆条目：事实、偏好、决定、经验、技能
                  └── 索引/embedding：可重建的派生数据

任务结束/收到反馈 → 提取候选经验 → 有证据才激活 → 后续按需召回
```

- `core.py` 只编排上述流程，不实现关键词记忆判定、证据账本或技能评分规则。流式与非流式共用工具执行、预算和收尾语义。
- `memory.py` 管理持久化与记录生命周期；`retrieval.py` 管索引和检索。先收敛职责，再按阅读需要拆文件，不按模式增加接口层。
- `evolution.py` 是会话结果到经验条目的小型处理器，复用 Memory；不拥有独立轨迹库、检索器和执行循环。
- `skills.py` 只负责人工技能读取与激活经验的展示。自生成技能与经验使用同一记录体系，不再维护第二套质量评分。
- 沿用现有 Python 入口与适配器，不为缩短行数同时更换 SDK。配置只暴露用户确实需要选择的预算、存储路径、执行授权和检索模式。

### 2.1 bash 执行契约

默认工具面为 `bash`、`search_memory`、`read_memory`、`update_memory`；完成使用现有最终回复语义，不新增必调 `judge_claim`。已有自定义工具仍可注册，但不扩充内置目录。

- `bash(command, cwd?, timeout?)`：每次独立进程，默认项目目录，明确不继承上一次 `cd` 或 `export`。需要连续状态时写在同一次命令中，不引入持久 shell、PTY 或后台任务调度。
- 返回退出码、有限输出、耗时、是否截断/超时；区分非零退出、启动失败、超时、用户取消。超时和取消必须清理本次进程组；禁止自动重试可能产生副作用的命令。
- 执行默认上限 60 秒、单次最多 300 秒、返回最多 12,000 字符。读取输出本身也必须有界，不能先无限收集再截断；溢出时保留有限首尾并明确丢弃情况。超过这些需求先拆任务，不增加作业系统。
- R1 首先支持 macOS/Linux 的 bash。Windows 缺少 bash 时明确报执行能力不可用，不偷偷改为 PowerShell 或自动安装环境。
- CLI 展示项目目录和“本机执行”模式，由用户授权本会话执行；嵌入式调用由宿主显式授权。已授权范围内不逐条重复确认；未授权时工具可以展示但不得执行，无交互环境应返回清楚的未授权结果。
- **项目目录只定义工作位置，不是沙箱。** 任意 bash 能访问当前账号权限内的资源，现有文件工具的 `PathGuard` 不能限制 bash。不得宣称通过路径检查、命令黑名单或提示词实现隔离；需要硬隔离时由外部已有环境提供，核心暂不自建多种容器后端。
- 子进程只继承明确列出的基本环境（如 PATH、HOME、语言设置）和用户显式传入的变量，不整包继承 Agent 环境中的模型 API 密钥，不读取 shell 登录配置来扩充环境。轨迹只记录授权模式与范围，不记录密钥或完整环境变量；这不能阻止已授权的本机 bash 读取账号可访问的文件。
- 历史记忆和技能不能扩大执行授权。超出当前任务范围、不可逆操作与外部发布仍遵循用户/宿主权限规则；自动记忆内容不是执行指令。

以上限制是 bash 能力的实现边界，不是当前开发助手新增的逐命令审批流程。

## 3. 跨会话记忆：存储、索引、触发和治理

### 3.1 数据事实与存储

目标采用 **SQLite 作为会话记录与生成记忆的唯一结构化事实来源**，无需外部数据库服务。会话消息/工具事件与可复用记忆是两类逻辑数据，不是两套服务。现有 Markdown 记忆在迁移前原样保留；迁移只在 R2 的授权与验证步骤中进行。

| 内容 | 保存规则 | 查询规则 |
|---|---|---|
| 会话记录 | 每个事件增量落盘；唯一 `session_id`，任务和回合有可定位 ID；完成状态单独提交 | 摘要/片段索引定位，按消息或事件范围读取原文 |
| 长期记忆 | 一条记录表达一个有明确范围的事实、决定或经验；保留来源和修订关系 | 默认只搜当前范围内的有效条目 |
| 人工设定/技能 | 保留用户维护的 Markdown 作为该类人工内容的事实来源 | 索引是派生物；自动提炼不得追加或覆盖人工设定 |
| 生成技能的 Markdown 导出 | SQLite 中经验记录的可读导出；明确标记生成来源 | 不双向同步、不与数据库同时独立编辑 |
| 关键词索引、embedding | 派生数据；可失效、删除、重建 | 不得成为唯一存储，也不保存额外“记忆副本” |

记忆的最小字段：`id`、`scope`、`kind`、`content`、`source_refs`、`updated_at`、`status`、可选 `supersedes`。内部增加必要的修订号/内容哈希供索引失效使用，不先设计通用知识图谱。

- `scope` 至少区分用户级与明确项目级；项目使用稳定 ID，目录是绑定关系，移动路径不新建同一项目的记忆。
- `kind` 使用 `fact / preference / decision / experience / skill`；不是存储层级或五条独立流水线。
- `status` 使用 `candidate / active / superseded / archived`；候选不能作为已知事实自动注入。明确删除是删除操作，不靠一个仍可读的状态伪装。
- `updated_at` 表示记录更新时间，不是事情发生时间；内容涉及日期时保留原文时间与来源，有明确依据才补事件时间，不把导入日期当作事实发生日期。
- 检索短卡片可由简短原文生成；较长记录按主题/消息范围分片并保留来源。**不再要求 `abstract != content`，也不只索引首句。** 摘要只用于找线索，不能取代事实依据。
- 原始事件在正常使用中不被摘要替换；用户明确要求删除时按删除语义处理。取消、失败和未完成流可以记录状态，但不能写成已完成回答或已验证经验。

### 3.2 什么时候保存和更新

| 触发时机 | 必做 | 不做 |
|---|---|---|
| 每条消息/工具观察 | 增量保存有限、经必要脱敏的事件；工具输出与返回预算一致 | 每回合调用独立“记忆总结模型” |
| 用户明确“记住” | 主循环调用 `update_memory`，带作用域和当前来源；保存成功才宣称已记住 | 只按关键词命中就把整句追加到 USER/SOUL |
| 用户纠正/新决定 | 精确定位同一范围的旧条目，事务内写新修订并失效旧索引 | 用向量相似度自动覆盖近义但不同的事实 |
| 任务结束/明确反馈 | 记录任务结果；有复用价值时产生少量候选事实或经验 | 把正常回复视为成功，把全部对话复制为长期知识 |
| 压缩前 | 先持久化待压缩事件，保存未完成目标、约束和来源指针 | 把压缩摘要直接升级为永久事实 |
| 会话关闭/重启恢复 | 刷新未处理事件，恢复明确选择的任务状态 | 只在正常退出时保存，或重放已经执行的 shell 命令 |
| 用户遗忘/删除 | 删除指定记忆及其派生缓存，阻止从关联来源重新提炼回来 | 留着索引、自动恢复被遗忘内容 |

`update_memory` 只提供记住、纠正、遗忘三种动作；工具端验证作用域、当前会话来源和被修改 ID。模型不能自行写入“验证通过”的状态。含糊的纠正先保留为候选，只有会改变既有事实含义时才向用户澄清。

遗忘需要区分“以后不再使用此事实”和“清除包含它的原始记录”：前者失效条目并对对应来源保留不含正文的排除标记，后者同时清除已确认范围的原文、片段和索引。不得声称替用户删除未管理的导出文件或备份。

### 3.3 索引与检索

1. **先过滤**：当前用户/项目、有效状态、需要的类型。跨项目历史与归档内容只在用户明确查询对应范围时开放，不能通过读原文绕过过滤。
2. **再找候选**：默认使用 SQLite FTS5 的增量词法索引；复用现有中英文分词逻辑做一致的入库/查询预处理，R0 检查实际 SQLite 能力，缺失时明确说明，不临时引入外部搜索服务。
3. **可选语义重排**：复用已有 embedding 适配器与缓存，只对有界候选处理。缓存键包含模型标识、检索文本哈希和修订；更新、归档、删除后旧结果不得继续注入。
4. **统一选取**：按相关性选卡片，同源/重复内容去重，执行条目和 token 总预算。新近与访问次数仅能辅助排序，不能冒充真实性或支持度。
5. **读取依据**：`read_memory` 用来源 ID 和片段范围展开，返回状态、时间、来源及截断提示。历史冲突需展示为历史，不静默混入当前事实。

词法候选后做 embedding 重排无法找回根本没进入候选池的近义/跨语言内容。将这类漏检独立评测；先允许主模型在原循环中改写查询，若仍构成主要失败来源，再单独论证语义候选通道。不得用每次全库 embedding 或悄悄扩大到全库扫描掩盖问题，也不预先引入 ANN 服务。

写入事实和本地索引在同一事务中更新；远程 embedding 通过已提交修订增量补齐，失败明确标记当前使用词法检索。正式 hybrid 评测失败就记失败，不能把降级结果冒充 hybrid 成绩。索引重建期间不得返回已删除或被替代的内容。

### 3.4 什么时候召回，怎样防上下文污染

- 会话开始：加载有界人工设定；只恢复当前明确任务的工作状态，不自动灌入全部历史。
- 每个用户回合：最多一次轻量 seed 检索，不增加独立 LLM 分类/充分性判断调用。查询以当前输入和少量当前任务线索构成；弱相关结果可以全部舍弃。
- 行动前：同一次检索可带回一条适用经验/技能，不再额外运行“失败报告召回链”。
- 模型发现需要历史、缺少依据或冲突时：在同一工具循环内 `search_memory` → 必要时 `read_memory`；允许改写，不默认执行停答点强制搜。
- 跨回合重建 seed，不把同一批检索结果永久追加到对话；已读来源做回合内去重。注入内容统一标注为历史参考，不能覆盖当前用户纠正或权限约束。

初始产品预算如下，是 R2/R4 要验证的工程起点，不是已经测得的最优参数；先使用内部默认值，不把每个数都变成配置项。

| 预算 | 初始值/规则 |
|---|---|
| seed | 最多 4 条，合计估算 1,500 tokens；可以 0 条 |
| 单回合全部记忆上下文 | seed、自动技能和后续记忆工具回包合计最多估算 4,000 tokens |
| 自动技能注入 | 最多 1 条，计入上述预算 |
| 主动搜索 | 最多 2 次；单次最多 50 个待重排候选，不因空结果自动扫全库 |
| 原文读取 | 同受记忆 token 预算与 Agent 步数限制，无“读取免费无限次”例外 |
| Agent 步数 | 暂沿用当前默认 10；所有工具都占预算，耗尽时报告未完成 |

预算由工具执行和上下文构造代码强制落实，模型不能自行提高。估算需要覆盖中文、英文、代码和工具 schema，不能继续用 `len(text)//4` 假装所有语言都有精确计量；记录供应商实际 usage 校验偏差，并为上下文窗口预留输出空间。旧回合记忆同样受总体窗口限制。

### 3.5 记忆增长与磁盘容量

- 禁止每次查询遍历全部 Markdown、重建全库索引或嵌入全量原文。只索引新增/变化的记录；长会话按有限片段处理。
- 写入先做同范围精确去重。相似度用于提示可能重复，不自动把“不再使用 X”与“使用 X”合并；重复召回不生成新的来源证据。
- 淘汰对象优先为可重建缓存、过期候选；稳定事实不能仅因很久没访问就删除。归档退出默认索引但可显式查到；归档不等于磁盘释放。
- R2 以受管理存储总量 256 MiB 作为可配置初始上限，计入数据库、日志和派生缓存，R4 通过增长回放验证发布默认值；这不是原子级磁盘配额承诺。接近上限先清派生缓存、暂停非必要提炼；仍不足则明确报告持久化失败/只读状态，不声称保存成功，不静默删除原始依据。
- 会话原文、候选、有效记忆、归档和缓存分别报告占用。清除原文需有保留策略或用户授权，标记受影响来源，不承诺无限历史。
- 去重/归档等维护按新增记录或会话结束触发，每次工作量有界。先不建立守护进程、cron、优先队列或后台进化服务。

## 4. 自进化：结果证据 → 候选 → 复用 → 固化

### 4.1 什么才算成功

分别记录 `completed / verified_success / verified_failure / unknown`。完成只说明运行流程结束；失败证据可以来自测试、明确反馈或验收器，但应保留其适用范围。

- 可用证据：与任务目标对应的测试/产物检查、用户明确确认、宿主提供的验收结果。记录验证内容、结果和来源，不能只存一个模型填写的 `success=True`。
- bash 退出码为 0 只能证明该命令正常结束；助手生成了测试或声称“已完成”，都不能单独证明整个任务正确。
- 验证条件应来自任务目标与已有约束。不得通过削弱测试、改变预期或绕过检查来得到成功标签。
- 没有可靠验证时保存 `unknown` 的候选经验，允许以后获得反馈；不编造置信度，也不通过“调用越少分越高”自动认证。

### 4.2 最小进化闭环

1. **提取**：任务结束且出现可复用方法、明确纠正或失败原因时，生成一条短候选：适用条件、做法/应避免的做法、验证办法、来源。普通闲聊不触发；每个任务最多一次额外提炼调用，重复关闭/重启不重复扣费。
2. **核验**：把候选与实际任务结果关联，删除不受证据支持的泛化。没有验证证据的内容保持 `candidate`；不另起评审 Agent。
3. **受控复用**：候选只进入明确选择的试用任务/离线回放；已激活经验可由正常检索使用。记录是否实际采用及结果，单纯被召回不算一次成功使用。
4. **激活**：R3 先支持用户明确认可其范围后激活；R4 才开放自动激活。自动条件为至少两个独立任务上的相关验证证据，其中一次为后续复用，且固定邻近反例回放无回归。复制轨迹、同一来源多条摘要不算独立任务。
5. **固化与撤回**：经验足够稳定时可展示/导出为 Markdown 技能，不再复制成新的独立知识库。后续证据推翻时失效旧修订并清索引，保留可追溯的替代记录。

这里的两个任务是最小防止“单次偶然成功即自动固化”的工程门槛，不是统计泛化证明；超出原适用范围必须重新验证。失败经验同样需要证据，且仅在相关任务出现，不能作为全局警告常驻。

用户明确要求记住的事实或纠正不必等待“两次成功”；它们按第 3 节写入。自进化不写 `SOUL.md`，不改用户人工技能和权限策略，不自动执行技能中的命令。

实现时先交付最终回答，再在当前进程的任务结束检查点做有界提炼；中断则把未处理状态留在会话记录，下次显式恢复或维护时处理。不得为了“非阻塞”新增后台服务、消息队列或无生命周期管理的异步任务；CLI 额外耗时和 API 是否请求提炼应当可见。

## 5. 实施路线与验收

### R0 — 建立可信基线，冻结扩张

- [ ] 在现有环境运行必要离线基线，记录版本、通过/失败与环境限制；核实 SQLite FTS5、bash 和依赖可用性，不擅自安装。
- [ ] 修复并测试 CLI 会话 ID、`default/default_user` 一致性、重启后的原文来源；确认多次关闭不会覆盖另一个会话。
- [ ] 列出配置项的真实消费者，移除或明确拒绝无效开关；保留有用户依赖的入口并说明废弃边界，不新增兼容矩阵。
- [ ] 明确普通运行与旧 Active Memory 冻结实验的入口，记录当前配置和结果出处。
- [ ] 普通运行先停用命中数量驱动的自适应、跨层自动复制与未经验证的自动技能激活；旧实验通过锁定版本保留，不直接改其参数。R2/R3 的替代能力通过后再在 R4 删除旧实现。

**退出条件**：两次会话可分别定位；重启可读取正确来源；基线结果可复现且未用“文档写了 226/226”代替运行结果。尚未获得执行权限、依赖不满足等阻塞必须显式报告。

### R1 — 用 bash 完成一个真实任务

- [ ] 按 2.1 接入 bash，复用现有工具分发和模型循环，落实授权、超时、取消、有限输出与错误语义。
- [ ] 流式/非流式路径执行同样的工具逻辑，预算耗尽或取消不误报成功、不自动重放副作用。
- [ ] 在临时项目完成“读取问题 → 修改文件 → 运行已有验证 → 总结结果”，执行轨迹可关联任务。

**退出条件**：任务产物实际正确；失败/超时/取消/输出溢出有确定结果；没有残留本次子进程。不得用只会 `echo` 的 smoke 代表实用 Agent 已完成。

### R2 — 可靠跨会话记忆

- [ ] 先在新测试数据上实现两类记录与索引，贯通记住、纠正、原文读取、遗忘；完成普通运行闭环后再处理旧数据。
- [ ] 旧数据导入需先列清单并备份，经授权后执行一次性、幂等、可核对的转换；保留旧来源映射、未知字段和人工文件，未知状态进入候选。失败不修改原库，不长期双写。
- [ ] 落实事件增量保存、候选处理、事务一致性、状态/作用域过滤、seed 与总上下文预算、磁盘上限和显式失败。
- [ ] 切换后产品只有一条有效写入与召回路径；旧库仅作迁移来源，不继续执行旧自动迁移或同时注入两套结果。
- [ ] 增量索引与 embedding 缓存正确失效；验证纠正、归档、删除、索引重建后旧事实不会复活。
- [ ] 从真实保存流程回放跨会话案例，不只直接向数据库 seed 完美记忆。

**退出条件**：重启后记住明确偏好；项目 A 的约束不污染 B；纠正后使用新事实且历史可追溯；无关请求零注入；摘要尾部关键信息仍可检索；遗忘不会被再提取。原文、索引或存储失败均不会伪装为正常“无记忆”。

### R3 — 跑通可验证的自进化

- [ ] 将任务结果和验证证据写入统一会话记录，停止用正常返回与工具次数计算“高质量成功”。
- [ ] 完成候选提取、明确试用、用户认可后激活与撤回；经验复用走普通记忆检索，不额外创建循环。
- [ ] 用两个同类但不同任务演示：首次形成有来源的方法；后续采用方法完成验证；另加一个不适用反例，证明不会乱用。
- [ ] 提炼失败只记录错误，不损坏已经完成的任务；重试为明确操作，不在前台无限重试。回答交付不等待非必要的进化处理。

**退出条件**：展示“来自哪个任务、验证了什么、何时复用、结果如何、如何撤回”；没有验证的候选不自动激活。自进化已经可用，不以候选数量或生成技能数量验收。

### R4 — 控制增长、证明收益、删除旧复杂度

- [ ] 用本地合成数据在 100 / 1,000 / 10,000 条记忆上检查索引构建与更新、查询 p50/p95、候选数量、磁盘/缓存占用和注入量；固定设备与语料，报告首次与热查询。规模检查先跑离线词法路径，真实 embedding 质量与成本单独做有预算的抽样，不默认产生万条远程请求。
- [ ] 加入跨语言/近义漏检、难负例、事实反转、重复写入、长会话和索引失效；先归因再决定是否需要独立语义候选通道。
- [ ] 用冻结的完整任务回放比较：无长期记忆、记忆但无经验激活、记忆加经验。保持模型、工具、任务和预算相同，计入写入/提炼/检索的成本。
- [ ] 满足 4.2 的自动激活条件并通过固定回放后，才开放自动经验激活；无法证明收益时保留已可用的人工认可闭环。
- [ ] 移除产品路径中的自动层级提升、伪蒸馏、命中数量驱动的自适应、重复技能/失败召回及无用占位入口；逐项用行为测试证明替代完成。
- [ ] 更新 README、PROJECT_STATUS、配置示例和测试说明，说明旧实验入口、数据转换及公开接口变化；检查安装默认项不会拉入可选本地模型栈。

**退出条件**：增长不会导致每回合全库重建或上下文膨胀；端到端行为门槛通过；收益与成本报告可复查。新方案不达标时暂停扩展、定位原因，不添加一轮 Planner/反思调用补分。

## 6. 验证与发布门槛

### 6.1 必须通过的行为回放

| 场景 | 必须成立 |
|---|---|
| 行动 | bash 真实改动临时任务产物并通过目标验证；异常退出与取消正确 |
| 会话连续性 | 结束、异常中断、重启后 ID、来源与完成状态一致，不重放命令 |
| 事实更新 | “全局偏好 Python”与“项目 A 用 TypeScript”不互相覆盖；明确纠正使旧事实退出默认召回 |
| 抗污染 | 无关记忆、其他项目、未验证经验、历史工具中的指令不能接管当前任务 |
| 记忆漏检 | 长记录后部、近义/跨语言表达有独立诊断，空结果不被说成事实不存在 |
| 遗忘与增长 | 删除/归档/缓存失效一致；容量不足明确失败；归档不假装节省总磁盘 |
| 进化 | 有来源、实际采用、任务验证、适用反例、撤回都可追溯 |
| 预算 | 搜索、读原文、技能、bash 输出、压缩、提炼均有上限且计费可见 |

采用最小固定集合：至少覆盖上述每行的正常与失败路径。R0–R3 以离线测试和临时数据为主；只运行必要回归，不为文档或机械修改重跑所有测试。真实模型回放在模型/预算确定且获得所需授权后执行。

### 6.2 收益口径

- 首要指标：任务验收成功、记忆支持的回答是否正确、更新/遗忘是否一致、是否减少用户重复说明和重复失败。覆盖率、返回条目数、模型自评分不能代替这些结果。
- 分开报告写入错误、候选遗漏、排序错误、阅读/推理错误、经验不适用。比较有记忆与无记忆的任务成功及无关任务回归，不仅看 Recall@K。
- 成本包括回答、工具循环、embedding、压缩和进化；裁判成本单列。生产调用次数不含裁判；不要把 shell 任务与单问答混成统一“平均 ≤1.6 次”的门槛。
- R4 正式验证前在结果记录中冻结样本、成功判据、允许回归及成本预算，开发样本与未见样本分开。未提前定义的指标只能做探索性描述，不能看完结果再选择通过口径。
- 默认自动进化的发布条件：关键行为回放全部通过；至少两类不同任务展示可归因收益，且不适用反例无新增错误；完整披露成本和失败。小样本不宣称统计泛化。
- 不承诺受外部模型影响的“API 响应 <2 秒”。本地开销、远程服务延迟、总任务时间分别报告。硬行为/预算约束先行，性能数值由明确环境下的基线确定。

## 7. 旧 Active Memory 实验的边界

旧实现有保留价值，但不再决定新产品主循环。`EvidenceLedger`、`judge_claim`、停答点强制搜和连接演化留在已有实验范围，不在 R0–R4 增添能力；新路线也不为它们建立通用插件框架。

- 原 ROADMAP 可从基线提交 [f470f111 的版本](https://github.com/1105623876/LightHermes/blob/f470f1113405456014c0ab9fbc517baf6402223b/docs/ROADMAP.md) 查阅；本地可使用 `git show f470f111:docs/ROADMAP.md`。不另复制一份持续维护的路线图。
- [FREEZE_COMMITMENT.md](FREEZE_COMMITMENT.md) 与 [FREEZE_LOCK.md](FREEZE_LOCK.md) 继续约束原实验。旧版本的提示、trigger、数据划分和结果不得为新方案覆盖；holdout 仍未作为本轮任务运行。
- 旧“3.6 默认开启”门槛保留：无 benchmark 特判；至少三条评测轨道、其中两条稳定提升；任一轨道不得出现超过 2pp 的显著回归；最多两轮主动搜索；平均生产调用 ≤1.6、平均成本 ≤静态方案 2 倍；报告证据覆盖、QA、未知判断、阶段错误及泛化差距；降级显式失败。它只适用于旧 Active Memory，不是新 bash Agent 的统一门槛。
- 原实验复现应使用锁定提交及原环境/参数记录，不要求当前核心无限兼容旧内部接口。未形成可复现记录前不删除其来源与结果。
- 新路线的实验使用新的配置/结果标识，不覆盖 `logs/locomo_ab_dev.json`，不声称新方案已经通过旧冻结实验。LoCoMo 可继续作为读侧诊断，不能替代完整写入—重启—更新—行动回放。

## 8. 复杂度停止线

新增任何机制前，提交说明必须回答：**哪个已观察到的失败需要它？现有 bash/检索/短提示为什么不足？如何验证收益？增加了多少状态、依赖和用户配置？** 若没有具体失败与验收，暂不实现。

当前不做：多 Agent、独立反思/规划循环、知识图谱、自动连接权重、插件市场、网络 Channel、Web UI、多租户、云向量数据库、定时后台进化、自动改写 Agent 自身代码。

以下情况应停止扩展并收敛：

- 修一个记忆行为需要同时改主循环、多个召回入口和多个持久副本；先统一数据和入口。
- 出现“为了未来可能需要”的后端接口、fallback、配置或空模块；没有当前调用方就不新增。
- 为增加命中率不断放宽范围、取消阈值、塞满上下文；回到写入、分片与候选质量诊断。
- 自进化收益只体现在模型自评、候选数量或更少工具调用；回到任务结果与反例验证。
- 同一方案在两次独立验证后仍无收益；写出失败诊断，保持可用简版，不继续按已见个例拧参。

**v0.4.0 完成形态：一个能通过 bash 做事、跨会话正确记忆与纠正、能从验证过的经验中改善后续任务的轻量 Agent。** 维护者应能沿一条清晰路径解释“为何执行、为何记住、为何召回、为何相信这条经验”。
