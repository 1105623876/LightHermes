## 当前运行闭环

- R0/R1：一个 Agent 循环，默认 bash + 三个记忆工具；bash 按会话/宿主授权，有限输出、超时/取消清理进程组。不声称是系统沙箱。
- R2：`LightHermes → RuntimeMemory → MemoryStore` 为唯一产品记忆路径。SQLite 保存事件、长期条目、来源与排除标记；意图先于工具副作用保存，取消/失败/完成分别记录。正常完成不等于任务已验证。
- 修订、归档、遗忘事务性失效 FTS5 与向量；遗忘排除来源回合，防止再次提取。模型 erase 只预览，宿主凭指纹执行明确范围的原文删除。
- 用户/项目 scope 由宿主固定；project_id 为稳定标识。SOUL、默认用户 USER 与人工技能保持只读。
- R2.5：主模型可 capture 用户直接表达的稳定事实、偏好、决定，必须引用当前消息原话，每回合最多三条。原话校验只验证出处，不证明归纳正确。
- 默认 FTS5；显式配置 memory.semantic 后，以同库 entry_vectors 提供独立语义候选。每回合最多 16 条正文向量、3 次查询向量；缓存命中不重新嵌入。积压/服务故障显示 partial/lexical，不掩盖失败。
- 本地向量查询对当前范围已索引条目线性扫描。R4 合成规模验收：100/1,000/10,000 条 × 1024 维热查 p50 约 16/161/1612 ms，万条主要耗时为 JSON 解码；管理存储约 244 MiB，接近默认容量。长记录预览定位词法命中片段；纯语义命中展示开头，可按 ID/offset 展开。
- 记忆上下文共享 4000 UTF-8 字节上界，seed 最多 4 条/1500 字节，主动搜索最多两次。来源元数据最多展示 8 个 ID 并报告总数；完整来源保留在数据库与宿主 experiences() 中。尚未校准中文实际 token 开销。
- 默认受管理容量 256 MiB，含 SQLite sidecar 与日志；是应用检查，不是 OS 硬配额。事件常见凭据脱敏及长度限制不是通用秘密检测。

## R3 已交付：显式验证式学习

- `evolution.enabled: true` 开启学习接口，默认仍关闭；不会每回合自动提炼，也不自动修改代码或人工技能。
- 回答交付后，宿主调用 `learn(verification, outcome=...)`，提供实际检查或明确用户反馈。模型最多一次额外请求，只生成一条有适用条件、方法、验证规则的 candidate，或返回无候选。
- 请求前保存 attempt 标记；重复调用/恢复同一任务不自动付费重试。提炼失败返回明确状态，不改变已交付回答；存储错误不伪装保存成功。
- `run(..., trial_experience=ID)` 只为该任务展示候选；其他任务看不到候选。宿主反馈 `adopted=True` 必须代表实际采用，单纯被召回不算使用。
- `review_experience(..., action='approve', reason=...)` 要求最近一次已采用试用验证成功，再明确认可适用范围。激活与审计来源同一事务提交；激活后走普通记忆检索。
- revoke 退出召回。宿主确认已采用试用失败时，已激活条目归档；不能用早期成功盖过后续失败证据。没有自动激活或统计泛化保证。
- CLI 提供 `/learn`、`/experiences`、`/trial`、`/approve`、`/revoke`；用法见 README。宿主验证是信任边界，框架不是验证结果的独立裁判。
